## 이 프로그램이 하는 일

로그인한 사람마다 **자기 할 일 목록을 따로** 가지고, 등록·조회·수정·삭제·완료 표시를 하는 웹 애플리케이션입니다.

| 기능 | 설명 |
|---|---|
| 회원가입 / 로그인 | 이메일과 비밀번호로 가입하고, 로그인하면 일정 시간 유효한 로그인 증표(JWT)를 받습니다. |
| 내 할 일 관리 | 할 일을 추가하고, 글자를 고치고, 완료 표시를 하고, 지웁니다. |
| 데이터 분리 | 다른 사람의 할 일은 보이지도 않고, id를 알아내도 고치거나 지울 수 없습니다. |
| 초대 코드(선택) | 설정해 두면 코드를 아는 사람만 가입할 수 있습니다. 체험판 운영용입니다. |

규모는 작지만, 웹 서비스의 기본 뼈대인 **"누가 로그인했는지 확인하고 → 그 사람의 데이터만 다룬다"** 를 처음부터 끝까지 갖추고 있습니다. 영업관리, 점검표, 요청 접수함처럼 "사람별·건별로 상태를 관리하는" 업무 도구는 대부분 이 뼈대 위에 항목만 바꿔 만들 수 있습니다.

## 장점

1. **사람별 데이터 분리를 서버가 보장합니다.**
   조회·수정·삭제를 할 때마다 "로그인한 사람의 것인지"를 데이터베이스 조건으로 확인합니다. 화면을 조작해도 남의 데이터에 닿지 않고, 이 동작은 자동 테스트로 확인합니다.
2. **보안 기본기를 표준 방식으로 갖췄습니다.**
   비밀번호는 BCrypt로 암호화해 저장하고, 응답이나 로그에 남기지 않습니다. 로그인 토큰은 Spring Security 표준 기능으로 검증하고, 서명 키는 코드가 아닌 환경변수로 받습니다.
3. **설치 없이 바로 실행됩니다.**
   기본값은 메모리 DB(H2)라서 Java만 있으면 바로 실행됩니다. 운영할 때는 환경변수만 바꿔 PostgreSQL이나 MySQL에 연결합니다.
4. **체험판으로 공개하기 쉽습니다.**
   초대 코드 설정 하나로 가입을 제한할 수 있습니다.
5. **바뀌면 바로 알 수 있습니다.**
   가입·로그인·할 일 전체 흐름, 잘못된 입력, 남의 데이터 접근 차단, 초대 코드까지 자동 테스트가 있고, GitHub에 올릴 때마다 자동으로 실행됩니다.
6. **고쳐 쓰기 쉬운 크기입니다.**
   데이터는 "사용자"와 "할 일" 두 가지뿐이라, 할 일에 항목(단계, 기한, 금액 등)을 더하는 방식으로 다른 업무 도구로 확장하기 쉽습니다.

## 응용해서 만들 수 있는 것

"할 일" 한 건을 다른 업무의 한 건으로 바꾸고, 필요한 항목을 더하는 방식입니다.

| 만들 수 있는 것 | 할 일 → 바뀌는 것 | 더할 항목 | 비고 |
|---|---|---|---|
| **영업 파이프라인 관리** | 할 일 → 거래 건 | 고객사, 단계(문의 → 제안 → 협상 → 계약), 다음 행동, 기한, 예상 금액 | 홈페이지 체험판으로 옮길 1순위 |
| **현장·시설 점검표** | 할 일 → 점검 항목 | 점검 위치, 점검일, 결과(양호/보수 필요), 담당자 | 사진 첨부는 별도 개발 필요 |
| **인허가·사업 진행 체크리스트** | 할 일 → 절차 단계 | 단계 순서, 제출 기관, 예정일·완료일, 메모 | 사업 건마다 목록을 따로 가짐 |
| **업무 요청 접수함** | 할 일 → 요청 건 | 요청자, 담당자, 상태(접수 → 처리 중 → 완료), 우선순위 | 여러 사람이 함께 쓰려면 권한 구분 추가 |
| **계약·회원권 만기 관리** | 할 일 → 계약 건 | 고객, 시작일·만기일, 갱신 여부 | 만기 임박 순 정렬, 알림은 별도 개발 |
| **고객 문의 기록** | 할 일 → 문의 건 | 문의 경로, 내용, 답변 여부, 후속 일정 | 영업 파이프라인과 연결 가능 |

공통으로 추가 개발이 필요한 것: 여러 사람이 같은 데이터를 함께 보는 권한 구분(팀·역할), 파일 첨부, 알림(메일·메신저), 목록 검색·필터.

## 첫 번째 응용: 모바일 프린터 운영관리 (v2.1)

같은 뼈대(로그인 → 내 데이터만 다룸) 위에, 2016~2017년에 실제로 매달 돌리던 **모바일 프린터 납품 업무**를 그대로 옮긴 운영관리 시스템입니다. 주소는 모두 `/printer/**` 아래에 있고, 할 일 기능과 섞이지 않습니다.

**한 달 흐름** — 신청 기간 열기 → 신청 등록 → 입금 확인 → 마감(미입금 자동 취소) → 배송 리스트 확정 → 발주서 → 품의 → 입고(시리얼) → 시리얼 배정 → 발송(송장) → 배송 완료 → 계산서 요청·발행(개인 앞/본사 앞) → 본사 수금 → 월 마감 보고

**예외 처리** — 신청 취소·환불, 기종 변경, 반송 후 재발송, 반품(회수 후 재고 복귀), 불량 교환(선배송 후 회수), AS(생산 2년 이내 무상), 계산서 발행 후 환불 시 정산 조정

| 구분 | 내용 |
|---|---|
| 동작 | 기획서의 동작 21개를 하나씩 API로 구현. 상태에 맞지 않는 동작은 거부(409)하고 이유를 한국어로 돌려줌 |
| 대시보드 | 이번 달 배송·계산서 대수, 재고, 본사 미수(기한 넘김 포함), 교환 회수 대기, AS, 환불 대기, "지금 챙길 일" 목록 |
| 기간 분석 | `GET /printer/analytics?from&to` — 기간 합계(배송·매출·수익·수금·신청·사후 처리)와 바로 앞 같은 길이 기간 비교, 45일 이하는 일별·넘으면 월별 추이, 영업장 순위 |
| 업무 할 일 | `GET /printer/tasks` — 남은 일을 처리 기한·중요도(1 긴급 / 2 중요 / 3 보통)와 함께, 처리할 화면·줄 정보까지 돌려줌 |
| 월 보고 | 영업 기준(배송 완료) / 회계 기준(계산서 발행) 대수, 영업장별 수량, 매출·매입·수익, 취소·반품·교환·AS 건수 |
| 작업 기록 | 모든 동작을 번호와 함께 기록 |
| 체험 데이터 | 빈 계정에서 `POST /printer/demo` 한 번으로 가상의 영업장 8곳과 1년 치 업무 생성. 이름·연락처는 모두 지어낸 값(가린 형태) |

가격 기준(체험용): 판매가 안드로이드 143,000원 · iOS 173,000원, 특약점은 개인이 143,000원을 먼저 입금하고 iOS 차액 30,000원은 본사 청구, 직영 영업소는 전액 본사 청구. 본사 미수 기한은 발행 후 30일로 가정했습니다.

## 2022 → 2026 무엇이 달라졌나

| 구분 | 2022 학습 버전 (`legacy-2022`) | 2026 업그레이드 (현재) |
|---|---|---|
| 기반 | Java 8, Spring Boot 2.6 | Java 21, Spring Boot 4.1 |
| 로그인 토큰 | 직접 작성한 JWT 필터, 책에 나온 서명 키를 코드에 그대로 사용 | Spring Security 표준(OAuth2 Resource Server), 서명 키는 환경변수 |
| 수정·삭제 | 소유자 확인 없음 → id만 알면 남의 할 일 변경 가능 | 항상 소유자 확인, 남의 것은 "없음"(404) 처리 |
| 비밀번호 | 회원가입·로그인 때 콘솔에 그대로 출력 | 출력하지 않음, 응답에도 포함하지 않음 |
| 입력 검증 | 없음 | 이메일 형식, 비밀번호 8자 이상, 할 일 200자 이내 등 |
| 오류 응답 | 예외 메시지를 그대로 노출 | `{error: "..."}`로 통일, 내부 오류는 로그에만 |
| 데이터베이스 | H2/MySQL, 접속 정보가 설정 파일에 기록 | 기본 H2, 운영 DB는 환경변수로 연결 |
| 가입 제한 | 없음 | 초대 코드(선택) |
| 테스트 | 기본 생성 파일 1개 | 통합 테스트 12개 + GitHub Actions 자동 실행 |

화면과 주고받는 API 모양(`/auth/signup`, `/auth/signin`, `/todo`, 응답 `{error, data}`)은 2022 버전과 같게 유지했습니다.

## 실행 방법

필요한 것: **JDK 21**

```bash
./gradlew bootRun          # Windows: gradlew.bat bootRun
```

`http://localhost:8080/` 에서 `{"service":"todo-api","status":"ok"}`가 보이면 정상입니다. 화면은 [프론트엔드 저장소](https://github.com/leeyou34/Webdevelopclass101frontend)를 함께 실행합니다.

테스트만 돌리려면 `./gradlew test`.

### 환경변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `JWT_SECRET` | (비어 있음) | 로그인 토큰 서명 키. 32자 이상. 비워 두면 실행할 때마다 임시 키를 만듭니다(개발용). **운영에서는 꼭 설정** |
| `JWT_EXPIRATION` | `1d` | 로그인 유지 시간 (예: `12h`, `7d`) |
| `DB_URL` | H2 메모리 DB | 예: `jdbc:postgresql://localhost:5432/todo` |
| `DB_USERNAME` / `DB_PASSWORD` | `sa` / (비어 있음) | DB 계정 |
| `DDL_AUTO` | `update` | 테이블 자동 생성 방식 |
| `CORS_ALLOWED_ORIGINS` | `http://localhost:5173,http://localhost:3000` | 화면이 열리는 주소(쉼표 구분) |
| `SIGNUP_INVITE_CODE` | (비어 있음) | 넣으면 이 코드를 아는 사람만 가입 가능 |

## API

| 메서드 | 주소 | 로그인 | 요청 | 응답 |
|---|---|---|---|---|
| GET | `/` | 불필요 | – | 서버 상태 |
| POST | `/auth/signup` | 불필요 | `{username, email, password, inviteCode?}` | `{id, username, email}` |
| POST | `/auth/signin` | 불필요 | `{email, password}` | `{id, username, email, token}` |
| GET | `/todo` | 필요 | – | `{data: [할 일...]}` |
| POST | `/todo` | 필요 | `{title}` | `{data: [할 일...]}` |
| PUT | `/todo` | 필요 | `{id, title, done}` | `{data: [할 일...]}` |
| DELETE | `/todo` | 필요 | `{id}` | `{data: [할 일...]}` |

운영관리 API(`/printer/**`, 모두 로그인 필요)는 [PrinterController](src/main/java/io/github/leeyou34/todo/printer/PrinterController.java)에 주소마다 기획서 동작 번호를 달아 두었습니다.

로그인이 필요한 요청은 `Authorization: Bearer <token>` 헤더를 붙입니다. 할 일 한 건은 `{id, title, done, createdAt, updatedAt}` 형식입니다.
